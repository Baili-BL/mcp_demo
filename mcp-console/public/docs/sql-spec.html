SQL 数据集规范

SQL 数据集会被发布成 MCP 工具。调用方和模型只能看到你写出的列、中文名和说明，所以保存前要做规范检查。 不通过就不能保存。占位符的写法见 SQL 占位符使用说明。

为什么要检查 只读且只有一条 禁止星号 列名 中文名和说明 LIMIT 占位符 可保存的例子

为什么要检查

数据集保存之后，可以在「发布工具」里变成一个 MCP 工具。模型通过 tools/list 看到参数名和说明，再决定怎么调用。SQL 如果含糊，工具就没有可用的字段定义。

编辑页点击「规范检查」，或直接点「确认编辑」。错误会列在结果区的「规范检查」页，补完后再保存。

只允许一条只读查询

MCP 工具只查数，不改库，也不在一次调用里执行多段语句。

✓一条 SELECT，或以 WITH 开头、最后落到 SELECT 的查询。
✕两条语句用分号隔开。去掉末尾那一个分号不算两条。
✕INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE、CREATE，以及 INTO OUTFILE。

原因：工具账号按只读来用。写操作或一次执行多段 SQL，会超出这个工具该做的事。

禁止 SELECT *

星号会随表结构变化，工具无法知道返回了哪些字段，也没法逐列写中文名和说明。

✕SELECT *，以及 t.*。
✓COUNT(*) 可以，它不是把整行展开。这种表达式要写 AS 别名。
-- 不行
SELECT * FROM base_from_ths_data

-- 可以
SELECT index_code, data_time, value
FROM base_from_ths_data

点击左侧数据表时，编辑器会插入该表已经同步到的列名，而不是星号。

列名必须是标识符

输出列名会成为工具 schema 里的字段名，调用方按这个名字传参、读结果。所以列名要用字母或下划线开头，后面只含字母、数字和下划线。

✓index_code、data_time、SUM(value) AS total_value
✕表达式没有 AS 别名，或别名带空格、中文、点号。
✕两个输出列同名。用 AS 区分。

每个输出列都要下定义

规范检查页会列出输出列。每一列都要填：

  • 中文名：给人看的字段名，例如「指标代码」。
  • 说明：这个字段是什么、调用时怎么用。这段文字会写进工具参数的 description，模型靠它选择参数。

缺任何一列的中文名或说明，都不能保存。再次打开数据集时，这两项会回显。

配置字段里的「AI 补齐」会根据当前数据源里的字段注释，以及列名本身，补上还空着的中文名和说明。已经写过的内容不会被盖掉，补完后仍可再改。

编辑器顶部的「AI 生成 SQL」按当前数据源已同步的表和字段注释起草一条 SELECT。它只写入编辑器，不会直接保存。

表关联时请写出 表别名.列名。两边都有的列（例如两张表都有 index_code）要用 AS 分成两个输出名，否则规范检查不通过。AI 补齐会按别名找到来源表，说明里带上来自哪张表。

没有 LIMIT 只提示

SQL 里可以不写行数限制。没有它时，规范检查给一条提示，仍然可以保存。

  • MySQL 写 LIMIT 100。
  • Oracle 写 FETCH FIRST 100 ROWS ONLY，不要写 LIMIT。数据源上会标出类型。
  • 编辑页预览最多 100 行。
  • 发布成工具后，默认最多 500 行，上限 5000。

行数上限在调用侧控制，避免一次把整表返回给模型。

占位符

占位符的类型、默认值和生效范围，仍按 SQL 占位符使用说明 配置。规范检查会带上那些错误。

用在 SELECT 列表里的值、表达式、条件占位符，必须设置全局生效的默认值。否则工具不传参时，这一列没有可用的值。

可保存的例子

SELECT
  index_code,
  data_time,
  value
FROM base_from_ths_data
WHERE index_code IN ('$val{index_code}')
LIMIT 100

然后在「规范检查」里为 index_code、data_time、value 填上中文名和说明，再点「确认编辑」。
