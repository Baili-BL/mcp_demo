服务注册与工具注册

管理台上的 MCP 服务不是「填个 URL 就算上线」。开发工程师必须先介入实现，再登记服务、再登记工具。 控制台只做发现、核对与授权，不代替写工具。

两件分开的事

服务注册工具注册
对象 一个可拨号的 MCP 进程（端点 + 协议） 该进程 tools/list 暴露的每一个工具
谁做 开发提交，管理员确认上线 开发在代码里 @mcp.tool；控制台探测或手工补元数据
完成标准 健康检查通过，端点可 initialize Schema 与线上 tools/list 一致，已编入工具集
禁止：先签发生产 Key，再补工具。没有工具集的服务对用户不可见。

开发必须提前介入

产品提「要行情 / 要 CRM / 要数仓」时，开发先做数据契约，而不是先做管理台表单。

  1. 确认上游：哪个平台、哪套库、只读还是可写、有无跨库 JOIN。
  2. 写出工具清单：名称 snake_case、入参、返回字段与错误码。
  3. 本地 FastMCP 跑通 tools/list / tools/call。
  4. 到管理台登记服务（名称、code、端点、协议 HTTP/SSE）。
  5. 登记或同步工具；创建工具集；再申请联调 Key。

服务注册字段

字段说明
名称 / code如 品种行情服务 / futures-market-mcp
协议Streamable HTTP 或 SSE，与客户端 type 一致
端点完整 URL，如 https://mcp.futures-data.cn/market/mcp
上游平台同花顺 / SMM / 钢联 / CRM / 数仓……可多选，禁止写死三家
负责人必须是已开通的开发工程师账号

工具注册

优先「从端点探测」：管理台用联调 Key 调 tools/list，把 name、description、inputSchema 写入目录。探测失败才允许手工粘贴 Schema。

工具编入工具集后才能被 Key 绑定。一个工具可以进多个工具集，但生产上按业务域拆分（行情 / 基本面 / 分析），避免一把 Key 打穿全部库。

跨平台服务

一个 MCP 服务可以包装多个内部系统（例如数据分析 MCP 同时打 CRM 与数仓）。注册时必须声明：

  • 每个工具对应哪一个上游，禁止在一个 tool 里隐式跨库 JOIN。
  • 失败时错误码带上游名，如 MCP_ERR_UPSTREAM_TIMEOUT:crm。
  • 限流按上游分别计算，避免 CRM 10 QPS 拖死数仓查询。
