MCP 服务代码规范

给要实现或接入 MCP 的开发工程师。内部系统不等于可以随便跨库。 行情、钢联、CRM、数仓可能不在同一实例，MCP 层只做薄包装与路由，不在工具里拼一套新的数仓。

先按《工程开发流程图》走完实现与注册，再对照本节写代码。

三条原则

  • 薄包装：工具只查既有接口或只读 SQL，不重算业务口径。
  • 语义一致：返回字段与源系统一致（代码、单位、时间点）。
  • 错误透传：鉴权失败、参数非法、上游超时用 ToolError / 网关状态码，不吞掉。

工程结构

server.py    # FastMCP 注册、鉴权中间件、tools/list 说明
db.py        # 每上游一个路由函数，禁止在此写业务口径
.env         # 多数据源连接串；不要提交仓库
logs/        # invoke_log.jsonl；可写库时再双写 invoke_log 表

工具名 snake_case，与 base_from_mcp_invoke_log.tool_name 对齐。新增工具先改代码，再在管理台探测注册。

跨平台 / 跨数据库

做法允许禁止
一服务多上游 分析 MCP 内 search_crm_* 走 CRM，query_warehouse 走数仓 一个 tool 里 JOIN CRM 表和数仓表
连接 每源独立连接池、独立超时、只读账号 共用一个「万能」库账号打生产写库
配置 CRM_DSN / DW_DSN / METRIC_DSN 分环境变量 把三套库写进同一个 DB_HOST
失败 错误信息带上游名；部分失败不要假装全成功 catch 后返回空数组当「没数据」
事务 只读查询；日志异步写 跨库分布式事务
需要「客户 + 品种盈亏」时：Agent 先调 CRM 工具拿客户，再调数仓工具拿盈亏，在对话层拼接。 不要为了方便在 MCP 里开一个跨库 SQL。

工具实现约定

  • 参数全部校验；日期、枚举、limit 上限（序列 ≤ 5000 行）写进 description。
  • SQL 参数化，禁止字符串拼接。
  • initialize 可不鉴权；tools/list 与 tools/call 必须 Bearer Key。
  • 鉴权结果内存缓存 ≤ 60s；过期与 429 分开。
  • 日志：key / tool / 上游 / 耗时 / 行数 / 脱敏后的 args。
@mcp.tool
def query_warehouse(dataset_id: str, limit: int = 500) -> dict:
    """按数据集从数仓取数。不访问 CRM。"""
    if limit > 5000:
        raise ToolError("limit 上限 5000")
    return dw.query(dataset_id, limit=limit)  # 只打 DW_DSN

上线检查单

  • 本地 MCP_AUTH_REQUIRED=0 仅本机；预发 / 生产必须开鉴权。
  • 管理台服务注册的端点与协议，和客户端 JSON 的 type / url 一致。
  • tools/list 与控制台工具目录一致后再建工具集、再发 Key。
  • 每个上游有独立超时与告警；不要让慢的数仓拖死行情工具的 P95。
