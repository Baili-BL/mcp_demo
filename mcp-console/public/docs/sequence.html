阶段〇 · 开发介入（原先缺失）

  1. 用户/产品向开发提出数据能力（「要螺纹钢现货 + CRM 客户」）。
  2. 开发向数据面确认：表、口径、是否跨库、只读账号。
  3. 开发实现 FastMCP 工具（薄包装，不在 MCP 层重算口径）。
  4. 开发在管理台注册服务（端点、协议、上游平台、负责人）。
  5. 开发注册工具：探测 tools/list 或提交 Schema，编入工具集。
  6. 管理台对端点做一次 tools/list 核对，不一致则服务保持「待发布」。
没有阶段〇就签发 Key，客户端会拿到空工具列表或打到未授权库。这是时序图必须把开发放在管理员前面的原因。

阶段一 · 用户开通与密钥

  1. 管理员生成邀请链接，标明内部员工或外部客户（见《用户管理与注册》）。
  2. 对方打开链接，填写手机号与登录邮箱完成注册。
  3. 账号变为正常后，再签发 Key 并绑定工具集。完整 Key 只展示一次。

阶段二～四

与控制台时序图一致：粘贴配置 → initialize（握手可不带 Key）→ tools/list / tools/call 强制鉴权 → 按工具路由到对应库 → 日志回写监控。

跨平台调用时，一次用户问题可能连续打两个 MCP 服务（行情 + 分析），密钥必须分别绑定对应工具集，不能靠「内网所以都能打」。
