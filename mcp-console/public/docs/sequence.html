Sequence · 全流程

时序图文档

交互时序图在顶部「时序图」。本页按管理员在控制台点下去的顺序写完整用户流程： 数据源 / 数据集 → 用户权限 → 创建服务 → 创建工具 → 创建工具集 → 开通用户 → 接入调用。

不要颠倒的顺序

  1. 数据源：数据准备 → 数据源。服务创建时只能勾已登记的源。
  2. 数据集：在源上建表 / 同库模型 / SQL 数据集。这是「创建工具」的数据侧入口。
  3. 用户权限：数据权限里配行策略、列策略、协作者。必须在发布工具和发 Key 之前。
  4. 创建服务：MCP 中心 → 创建 MCP 服务（端点、协议、勾数据源、可选透传身份）。
  5. 创建工具：探测 tools/list、工具目录手工登记，或「数据集 → 发布工具」；既有工具可申请读取数据集。
  6. 创建工具集：把各服务里的工具归集。没有工具集，用户 Key 绑不到任何工具。
  7. 开通用户：企微选人或导入注册，加入用户组（组决定 Grant 是否命中）。
  8. 签发密钥：接入与密钥，Key 归属用户并绑定工具集，把 url + Bearer 发给对方。
  9. 接入调用：用户粘贴配置 → list 只见工具集内工具 → call 按该用户套 Grant。
两套权限分开：工具集决定能调哪些工具；Grant 决定调数据集时看见哪些行和列。

1 · 数据源 / 数据集

管理员在「数据源」填写 DSN、只读账号、超时，测试连接并同步 schema。再到「数据集」建集：单表、同库 JOIN，或 SQL + 占位符。禁止跨源 JOIN。

定制协议（行情快照等）仍须开发先写 FastMCP；只要把已有表按人过滤，走数据集即可，不必新起进程。

2 · 用户数据权限

  1. 行权限：对全员 / 指定用户 / 用户组生效，可白名单绕过，未匹配可兜底为空。
  2. 列权限：隐藏或脱敏；仅对 TA 有效 / 仅对 TA 无效。
  3. 协作者：谁能改这个数据集和它的权限（use / manage）。
权限主体是用户和用户组，不是 Key。Key 只用来找出调用人，再套 Grant。

3 · 创建服务

  1. MCP 中心 → 创建 MCP 服务：名称、code、端点、HTTP 或 SSE。
  2. 勾选本服务读取的已登记数据源。没有的源先回第 1 步。
  3. 若该服务要读受控数据集，打开「透传身份」。
  4. 数据集服务 dataset-hub-mcp 由平台托管，发布数据集工具时自动挂上，一般不用再手建。

4 · 创建工具

来源在哪做结果
探测上游创建服务时勾选，或稍后探测 tools/list工具挂到该服务，出现在工具目录
手工登记工具目录粘贴 Schema探测失败时的补录
发布数据集数据集 → 发布工具挂 dataset-hub-mcp，Schema 随 Grant 走
申请读取工具目录勾选数据集 → 数据集侧批准写入 reads；生成中间视图后才算受控
工具进目录还不能给最终用户。必须进入下一步：创建工具集并勾选。

5 · 创建工具集

  1. MCP 中心 → MCP 工具集 → 创建。
  2. 从各服务勾选工具加入（可跨服务，不覆盖集内原有工具）。
  3. 也可在探测完成后「创建并绑定工具集」，再去签发密钥。

一把 Key 只绑需要的集，避免行情 Key 打穿 CRM / 数仓。

6 · 开通用户

  1. 内部：企业微信通讯录选人。外部或不在通讯录：导入注册（手机号 + 名称，可 Excel）。
  2. 加入用户组。行/列策略按组命中，未入组等于策略对其无效或走兜底。
  3. 接入与密钥：先选归属用户，再绑工具集，设 QPS / 日配额 / 到期。完整 Key 只展示一次。
  4. 把 url + Bearer Key 发给该用户。

7 · 接入调用

用户写入客户端配置并重启 → initialize（可无 Key）→ tools/list 只返回该 Key 工具集 → 提问后 tools/call。指标工具按 source 打库；数据集工具用 Key 归属用户编译 Grant，再打该集所在源。

8 · 监控

调用日志回写监控。关系树从用户 / 服务 / 数据集三边看：工具集是否绑上、Grant 是否生效、读取是否受控。
